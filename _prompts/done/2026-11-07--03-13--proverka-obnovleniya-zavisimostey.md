# Проверка обновления зависимостей

## Суть

### Проблема

В файле состава пакета повышены версии рабочих и служебных зависимостей. Несколько изменений переходят на новые
основные выпуски, поэтому обычной установки недостаточно: нужно проверить несовместимые изменения, сборку и поведение.

### Текущее состояние

Новые ограничения версий уже внесены пользователем, но файл закреплённых версий ещё не обновлён. Совместимость с
исходным кодом, средой выполнения и проверками проекта пока не подтверждена.

### Решение

Сопоставить изменённые версии с местами использования и официальными описаниями выпусков, установить зависимости,
устранить выявленные несовместимости без отката новых версий, затем выполнить полный набор подходящих проверок.

### Как будет

Проект будет использовать заявленные последние версии, файл закреплённых версий будет согласован с описанием пакета,
а сборка, статические проверки, испытания и запуск подтвердят сохранение функциональности.

## Исполнителю (LLM)

- Не изменять пользовательские правки, не относящиеся к обновлению зависимостей, и не создавать запись Git.
- Использовать официальные первичные источники для проверки несовместимых изменений основных выпусков.
- После каждого выполненного пункта сразу ставить отметку `- [x]`, записывать результат в заметки и показывать полосу
  из 64 символов: доля `█` равна доле выполненных пунктов с округлением, остальные символы — `░`; рядом показывать
  целый процент, следующей строкой — количество закрытых и всех пунктов. Отметки являются единственным источником хода.
- Если работа длится более двадцати минут, повторно показывать ход не реже одного раза в двадцать минут.
- Любой пункт начинать с независимой проверки, не выполнен ли он уже; повторный запуск должен быть безопасен.

## Этап 1. Область и риски обновления

- [x] Проверить разницу файлов состава и закреплённых версий, найти все места использования зависимостей и по
  официальным источникам установить требования среды и несовместимые изменения обновляемых основных выпусков.

## Этап 2. Установка

- [x] Установить заявленные версии штатным средством проекта, обновить файл закреплённых версий и убедиться, что
  дерево зависимостей разрешается без ошибок и неожиданных недопустимых одноранговых требований; синхронизировать
  проверенные версии рабочих и служебных зависимостей в `cli-template/package.json`.

## Этап 3. Совместимость исходного кода

- [x] Выполнить проверку типов и чистую сборку; при ошибках внести минимальные изменения для новых прикладных
  интерфейсов и повторить проверки до успешного результата.

## Этап 4. Поведение

- [x] Выполнить проверку качества, все автоматизированные наборы испытаний и краткую проверку запуска; подтвердить,
  что обновление не нарушило доступные проверяемые возможности проекта.

## Этап 5. Документация

- [x] Проверить документы библиотеки и шаблона командной строки; обновить их только при изменении требований,
  способов запуска или публичного поведения, затем зафиксировать окончательные результаты и перенести план в `done`.
